# 技能名称：code-updater

## 技能描述
代码自动生成与修改专家。接收需求变更影响报告后，自动修改工作区中的相关代码文件（SQL、Python、配置文件等），生成必要的测试脚本，并将所有变更提交到一个新的Git分支。

## 触发条件
- 用户指令包含"修改代码"、"更新代码"、"应用变更"、"生成DDL"、"更新ETL"、"代码升级"、"字段变更落地"等关键词
- 已有需求变更影响报告（可由 `requirement-diff-analyzer` 生成）

> **跳过条件**：如果变更影响报告为空，输出"无代码变更需求"。

## 输入格式
用户需要提供：
- 变更影响报告（Markdown格式，包含变更清单和影响对象）
- 工作区根目录路径（默认为当前目录）

## 输出格式
严格按照以下模板输出：

```markdown

**报告状态**：待测试 → 测试中 → 测试通过 → 已合并
**生成时间**：{YYYY-MM-DD HH:mm}
**Git分支**：upgrade/{需求编号}

## 执行流程

### 第一步：解析变更影响报告
- 提取需要修改的表、字段、ETL脚本、配置文件等
- 区分操作类型：新增、修改、删除

### 第二步：生成或修改代码文件
根据变更类型，执行以下操作：

**DDL修改**：
- 若新增字段，生成 `ALTER TABLE` 语句并追加到对应表的 `.sql` 文件中
- 若修改字段类型，生成 `ALTER TABLE MODIFY` 语句
- 若新增表，生成完整的 `CREATE TABLE` 语句
- 若删除字段，生成 `ALTER TABLE DROP COLUMN` 语句

**ETL脚本修改**：
- 对于SQL脚本：定位到相关行，修改字段列表、JOIN条件、WHERE条件、聚合表达式等
- 对于Python脚本：修改数据转换逻辑，确保兼容新字段
- 若变更涉及新增表或字段，自动在ETL中加入对应的读取或写入逻辑

**配置文件修改**：
- 如 `requirements.txt`：标记旧需求为废弃（添加 `[DEPRECATED]`），新增需求条目
- 如 `data_lineage.json`：更新依赖关系，加入新字段的下游记录

**重要**：所有修改必须保留原文件的格式和注释，不得删除无关代码。

### 第三步：生成测试脚本
- 创建一个 `test_upgrade_{需求编号}.sh` 或 `.py` 脚本，内容包含：
  - 在测试环境执行 DDL 变更
  - 运行修改后的 ETL 脚本（可使用小数据集）
  - 对比新旧逻辑的输出结果（若可能）
  - 检查关键指标是否在预期范围内
- 测试脚本应返回 0 表示通过，非 0 表示失败

### 第四步：提交到Git新分支
- 执行 `git checkout -b upgrade/{需求编号}` 创建新分支
- 将所有修改的文件添加到暂存区
- 生成提交信息，格式见输出模板
- 执行 `git commit` 提交

### 第五步：输出变更摘要
列出所有修改的文件路径、变更类型（新增/修改/删除），以及测试脚本的执行命令示例。

## 与上下游 Skill 的衔接

| 角色 | Skill名称 | 触发条件 | 传递内容 |
|------|-----------|----------|----------|
| 上游 | `requirement-diff-analyzer` | 输出确认后 | 变更影响报告 |
| 下游 | `scheduler-updater` | 代码变更完成后 | 代码变更摘要 |

**需求生命周期状态机**：
```
bi-requirement-parser → requirement-diff-analyzer → code-updater
                                                    ↓
                                          sql-code-generator (生成 SQL)
                                                    ↓
                                              sql-validator (EXPLAIN 验证)
                                                    ↓
                                            cluster-tester (集群测试)
                                                    ↓
                                              git-merger (合并确认)
                                                    ↓
                                          scheduler-updater (调度更新)
```

## 异常处理
- 若文件不存在或无法定位到需要修改的行，则中止并报告具体错误
- 若Git命令执行失败（如不在仓库中），提示用户手动创建分支
- 若修改可能破坏现有逻辑，输出警告并要求确认
- **对话退出条件**：最多追问 **3 轮**，每轮最多 **5 个问题**

## 特殊场景处理

### 空仓库初始化
如果 Git 仓库为空（没有任何提交），Skill 会自动执行初始化：

```bash
# 检测空仓库
git status  # fatal: not a git repository 或 nothing to commit

# 自动初始化
git init
git remote add origin {GITEE_REPO}
git checkout -b master

# 创建基础目录结构
mkdir -p sql/dwd sql/dws sql/ads etl test docs

# 提交初始结构
git add .
git commit -m "chore: 初始化项目结构"
git push -u origin master

# 然后创建版本分支
git checkout -b v0.0.1
```

## 注意事项
- 代码修改必须保留原文件的格式和注释
- 所有变更必须可回滚（使用 git revert）
- 测试脚本必须覆盖核心业务逻辑
- 提交信息必须清晰描述变更内容，便于 code review
- 禁止直接修改生产环境代码，必须通过 PR 流程
