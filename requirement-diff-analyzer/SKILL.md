# 技能名称：requirement-diff-analyzer

## 技能描述
需求影响分析专家。支持两种工作模式：

- **mode=upgrade**（升级需求）：当用户提供旧需求（如 REQ-001）和新需求（如 REQ-001-v2）时，对比两者差异，输出结构化的变更清单，并结合数据血缘元数据（data_lineage.json），评估影响范围。
- **mode=new**（新增需求）：当用户提出全新需求时，分析新表/新字段对已有下游报表的影响，检查资源竞争，输出完整的三级影响传播报告。

## 触发条件
- 用户指令包含"分析需求变更"、"对比需求版本"、"需求升级分析"、"需求diff"、"变更影响"、"版本对比"等关键词 → **mode=upgrade**
- 用户指令包含"新增需求影响分析"、"血缘影响分析"等关键词 → **mode=new**
- bi-requirement-parser流水线自动路由：升级需求→mode=upgrade，新增需求→mode=new

> **跳过条件**：如果两个需求完全相同，输出"需求无变更，无需分析"。

## 输入格式

### 必选参数
- **mode**：工作模式，取值 `new`（新增需求）或 `upgrade`（升级需求）

### mode=upgrade 输入
用户可以通过以下方式提供新旧需求：
1. 直接粘贴需求文本（包含编号、描述、涉及表、粒度、周期、指标口径等）
2. 指定文件路径，如 "读取 requirements.txt 中的 REQ-001 和 REQ-001-v2"
3. 由上游 skill `bi-requirement-parser` 输出的确认后需求文档

### mode=new 输入
1. 新需求的结构化描述（涉及表、字段、指标、维度、粒度、周期）
2. 由上游 skill `bi-requirement-parser` 输出的确认后需求文档

### CLI 调用示例
```bash
# 升级需求
requirement-diff-analyzer --mode upgrade --old-req "REQ-001" --new-req "REQ-001-v2"

# 新增需求
requirement-diff-analyzer --mode new --requirement "新增渠道保费月度趋势报表..."
```

## 执行流程

### 第一步：解析新旧需求
- 提取旧需求的完整字段：编号、描述、涉及表、粒度、周期、指标口径
- 提取新需求的完整字段
- 若字段缺失，按默认值补充（粒度默认"日"，周期默认"最近一个月"）
- 生成版本号（如 v1.0 → v2.0）

### 第二步：对比差异
逐项对比并标记变更类型：
- **字段新增**：新需求中有但旧需求中没有的字段、指标或维度
- **字段删除**：旧需求中有但新需求中已移除的
- **字段修改**：字段名、口径、类型、默认值发生变化
- **涉及表变更**：新增或移除关联的ODS/DWD/DWS表

### 第三步：评估影响范围
- 读取工作区中的 `data_lineage.json`（若不存在，则提示用户生成或手动创建）
- 根据变更的字段或表，查找下游依赖：
  - 依赖的 DWD/DWS 表及字段
  - 依赖的 ETL 脚本（SQL/Python）及行号
  - 依赖的调度任务名称
  - 依赖的报表/看板
- 输出影响清单

### 第四步：生成变更影响报告
将第二步和第三步的结果合并，输出一份 Markdown 报告

### 第五步：强制确认
- 报告末尾包含 **"业务确认"** 章节
- **确认后自动触发** `code-updater` skill，将变更应用到代码

## 与上下游 Skill 的衔接

| 角色 | Skill名称 | 触发条件 | 传递内容 |
|------|-----------|----------|----------|
| 上游 | `bi-requirement-parser` | 需求去重判定为"升级需求" + 审批通过后 | 原需求文档 + 新需求文档 |
| 下游 | `code-updater` | 本Skill输出影响分析报告且**人工审批通过**后 | 变更影响报告 + 解决方案 |

**需求生命周期状态机**（含审批门禁）：
```
bi-requirement-parser (需求解析)
        ↓ 需求文档生成
  ┌──── 需求去重检查 ─────────────────────┐
  │  → 新增需求：v1.0，直接进入影响分析    │
  │  → 升级需求：保留原版，进入变更分析     │
  │  → 重复需求：终止                      │
  └───────────────────────────────────────┘
        ↓ 非重复
  ┌──── 影响分析 + 审批门禁 ──────────────┐
  │  requirement-diff-analyzer             │
  │  → 输出变更清单 + 影响报告            │
  │  → 🔒 等待人工审批                    │
  │  → 审批不通过 → 终止                  │
  └───────────────────────────────────────┘
        ↓ 审批通过
code-updater (代码变更)
        ↓
sql-validator (语法验证)
        ↓
git-merger (合并确认)
        ↓
scheduler-updater (调度更新)
```

## 异常处理
- 若无法定位需求编号，提示用户提供完整的需求描述
- 若 data_lineage.json 缺失，仅输出基于字段名的模糊影响推测，并警告用户手动核实
- **对话退出条件**：最多追问 **3 轮**，每轮最多 **5 个问题**，超过限制建议线下补充

## 注意事项
- 变更分析必须基于血缘元数据，避免遗漏下游影响
- 所有变更必须可回溯，保留版本对比记录
- 高风险变更（如修改历史数据口径）需单独标注
